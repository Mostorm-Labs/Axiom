Skia 148 compatibility green phase (2026-07-25)

Replaced the removed mutable SkPath calls with SkPathBuilder while keeping
SkPath as the render cache. A changed tail chunk is restored into one builder
once, all points for that chunk are appended, and one path is detached after
the batch. New chunks likewise use one builder for at most 64 segments.
Unchanged frames continue to draw the cached SkPath directly.

This preserves the existing chunk and counter semantics. A full rebuild is
O(total points). Amortized incremental work is O(appended points + one replay
of the existing tail chunk), with that replay bounded to 64 segments; it does
not replay a growing path or create a path for every appended point. An
occasional chunk-vector growth may move the existing lightweight SkPath cache
entries before capacity is reused.

Three pixel-level regressions cover the changed behavior: preserving the old
path while appending a new tail, extending a cached one-point path into its
first segment without a full rebuild, and appending the 65th segment after an
exactly full 64-segment chunk. The boundary case also requires a second chunk
and verifies a pixel on the newly created vertical tail.
