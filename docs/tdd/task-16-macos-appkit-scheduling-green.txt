macOS AppKit frame scheduling GREEN phase (2026-07-26)

CanvasMetalView now uses the supported layer callbacks instead of drawRect.
It advertises wantsUpdateLayer/updateLayer for AppKit-managed updates and, for
the actual custom layer-hosting CAMetalLayer path, acts as the layer's weak
CALayerDelegate and calls MetalHost::drawIfNeeded from displayLayer. A native
frame request marks both the NSView and CAMetalLayer dirty; FrameInvalidation
still coalesces callbacks, so there is no display link, timer, or busy loop.
Detach clears the weak layer delegate before removing the native layer.

viewDidMoveToWindow resizes and then calls reschedulePendingFrame. That method
checks real pending work but deliberately ignores the old displayScheduled
coalescing result and reasserts the native display request. This covers a
Document invalidation issued before the view had a window.
