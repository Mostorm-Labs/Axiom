Official API inspection:
  Xcode 26.2 (17C52), macOS 26.2 SDK NSEvent.h at:
    /Applications/Xcode-26.2.0.app/Contents/Developer/Platforms/
    MacOSX.platform/Developer/SDKs/MacOSX26.2.sdk/System/Library/
    Frameworks/AppKit.framework/Headers/NSEvent.h

  The header declares tablet pressure in [0,1], tilt as two scaled axes in
  [-1,1], tangential pressure in [-1,1], and only rotation as degrees. It also
  declares tablet deviceID, proximity unique/system/pointing IDs, raw
  capabilityMask, and Pen/Cursor/Eraser/Unknown pointing-device types.

  Apple's Cocoa Event Handling Guide says drivers usually package tablet point
  input as mouse-event subtypes, while native tabletPoint events can occur
  between stylus-down and the first drag (among other exceptions). Therefore
  both responder paths must converge on one session; native points must never
  create an independent second Down.

RED setup:
  Pure C++ tablet model declarations and deliberately inert adapter/session
  stubs were registered with ten behavioral tests. A source contract was also
  registered for AppKit extraction and subtype-before-mouse-session routing.

Commands and observed results:

Evidence boundary:
