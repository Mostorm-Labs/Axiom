Task 19 macOS fixed layer-stack GREEN phase (2026-08-01)

The RED capability is now implemented by `CanvasCompositionView`. It creates
exactly three AppKit sibling views in fixed back-to-front order:

  Base Metal -> embedded native-view container -> Overlay Metal

The portable `SkiaSurfaceFramePlan` gives Base an opaque white clear and only
`LayerClass::Base`. Overlay has a transparent clear and only
`LayerClass::Annotation` plus `LayerClass::Chrome`. Neither frame plan paints
`LayerClass::Embedded`.

The two `CanvasMetalView` instances retain one `MetalRenderResources` group:
one `MTLDevice`, `MTLCommandQueue`, Ganesh `GrDirectContext`, and
`SkiaRenderer`. Each host nevertheless has its own `CAMetalLayer`, frame
invalidation state, drawable acquisition, and present. Base is opaque and
Overlay is transparent. The default hit-test owner is Overlay; setting
`embeddedInteractionEnabled` explicitly routes hit testing to the middle
container. There is no display link, timer, or continuous render loop.

Attach, resize, backing-scale change, and reattach use event-driven AppKit
display work. A detach clears the native attachment before
the AppKit layer is removed, and a later reattach requests a fresh frame for
the retained document. All host use and every potentially final
`MetalRenderResources` shared-pointer release are main-thread-affine.
