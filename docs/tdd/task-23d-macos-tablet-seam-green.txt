Implemented scope:
  - The platform-neutral seam represents tablet point source, phase, pressure,
    scaled two-axis tilt, tangential pressure, rotation in degrees, button
    mask, device identity, raw capabilities, and Pen/Cursor/Eraser/Unknown
    tool identity without importing AppKit into the pure C++ files.
  - Tool intent is explicit: Pen is eligible for a future ink conversion,
    Eraser is EraserPending, and Cursor/Unknown are Unsupported. Eraser,
    Cursor, and Unknown can therefore never silently become ordinary ink.
  - MacosTabletSession uses fixed arrays for at most eight proximate profiles,
    four active contacts, and four output samples. Associated mouse Down owns
    contact creation. Native tabletPoint input may update only an existing
    same-device contact and cannot create a second Down. Exact native/
    associated measurements are deduplicated.
  - Orphan, mismatched, unproximate, invalid source/phase, and capacity-
    overflow input fails closed. Duplicate Down cancels before replacement;
    proximity leave and lifecycle reset cancel contacts exactly once and clear
    device profiles. A contact retains the device/tool profile captured at
    Down.
  - CanvasPointerMetalView extracts tablet fields synchronously on the AppKit
    main thread through tabletPoint:, tabletProximity:, and associated mouse
    subtypes. Tablet-only getters are reached only after checking the native
    NSEvent type or a valid left-mouse type followed by its tablet subtype.
    An associated tablet subtype returns before the existing MacosMouseSession.
  - No event monitor, Electron call, IPC message, JSON object, or dynamic
    container was added to the input hot path. App/window resign, window close,
    detach, mode/document replacement, cancellation, and teardown reset the
    tablet session idempotently alongside the existing mouse lifecycle.
  - A modality switch cannot strand state in the other session. An associated
    tablet point first cancels and dispatches any ordinary-mouse preview before
    consuming the tablet sample. Conversely, an ordinary non-tablet Mouse Down
    resets tablet contacts and profiles before starting its mouse session, so
    a later native tablet update cannot rejoin a stale pre-mouse contact.

Deliberate fail-closed integration boundary:
  MacosTabletSample is not converted to the current PointerSample because that
  type cannot preserve tablet tool identity and scaled tilt semantics. Every
  tablet-session output is intentionally discarded inside CanvasPointerMetalView;
  no Pen, Eraser, Cursor, or Unknown sample is sent to the pointer delegate or
  mutates Document. Ordinary non-tablet mouse events retain the existing
  visible drawing path.

Independent review:
  The first review found a cross-modality P1 in which an associated tablet
  point could leave an older ordinary-mouse preview active. The implementation
  was corrected to dispatch Mouse Cancel before tablet consumption and to
  reset the tablet epoch before an ordinary Mouse Down. The same reviewer then
  reran the focused and complete gates above and returned PASS with no
  remaining P0, P1, or P2 findings.

Evidence boundary and pending work:
  The tablet behavior tests use constructed raw C++ records and the AppKit
  integration gate is source-level. This is not physical tablet, pressure
  accuracy, eraser execution, visible pen drawing, touch input, GUI automation,
  hosted macOS CI, or latency evidence. Interact mode still hit-tests embedded
  native content instead of the overlay. Coalesced/predicted pen input and a
  semantics-preserving tablet-to-whiteboard model remain future increments.
  The i5-1235U touch-to-visible-ink p95 target below 50 ms still requires the
  target Windows touch display and is not established by this macOS seam.
